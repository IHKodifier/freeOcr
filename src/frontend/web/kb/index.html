Dual-Layer Searchable PDF Architecture (ISO 32000-1)

A dual-layer PDF (commonly known as a "Searchable PDF") preserves the exact visual fidelity of the original scanned document while synthesizing an invisible, machine-searchable text layer directly aligned over the scan bitmap.

How freeOCR.me Synthesizes Dual-Layer PDFs:

  • Bitmap Preservation: The scanned page image is placed as the visible background layer at its original resolution and DPI. Stamps, hand-written annotations, and signatures remain visually intact.
  • Coordinate Normalization: Neural bounding polygons from the OCR model are mapped from pixel dimensions to standard PDF point coordinates (72 points per inch) with sub-pixel alignment:
    scale_x = page.rect.width / pix.width, scale_y = page.rect.height / pix.height.
  • Invisible Text Layer (render_mode=3): Using ISO 32000-1 compliant font rendering mode 3, text is rendered in an invisible glyph layer positioned over each matching scanned word. Users can highlight, copy, and search (Ctrl+F) with 100% geometric accuracy.

Preprocessing & Layout Heuristics:

  • Deskewing via Radon Transforms: Scanned pages frequently enter at slight tilt angles. Radon transform projections calculate horizontal skew (-15° to +15°) and automatically rotate pages prior to segmentation.
  • Adaptive Otsu Binarization: Separates foreground text from aged paper textures, background bleed-through, and coffee stains.
  • Dual Engine Routing: Clean, single-column documents route to OCRmyPDF/Tesseract on CPU for rapid <1.5s completion. Complex multi-column documents, math formulas, and nested tables dynamically route to our Baidu Unlimited OCR neural model (~6 GB weights) running on Nvidia GPU instances.

The Evolution of Portable Document Standards

Before the Portable Document Format (PDF) was invented by Dr. John Warnock in 1991 (the "Camelot Project"), sharing formatted digital documents across different operating systems was notoriously fragmented.

Key Milestones in Document Interchange:

  • PostScript (1984): A page-description programming language that allowed laser printers to rasterize vector glyphs. However, PostScript files required a full interpreter to execute, making fast screen previewing slow and resource-heavy.
  • PDF 1.0 (1993): Extracted declarative graphics from PostScript into an indexed binary stream, allowing pages to render on-screen independently.
  • ISO 32000-1 (2008): PDF was officially standardized by the International Organization for Standardization as an open format. Render mode 3 was codified to allow font characters to define bounding geometry and selection without coloring pixels.
  • PDF/A (Archive Standard): Forbids external font dependencies and encryption, ensuring documents can still be opened and rendered accurately 100 years into the future.

Zero-Retention Ephemeral RAM-Disk Security (Linux tmpfs)

Document privacy is the foundational design pillar of freeOCR.me. Traditional cloud converters save files to Amazon S3 or Google Cloud Storage buckets where they may persist indefinitely.

Our Kernel-Level Security Guarantees:

  • Volatile Memory Mount: Uploaded documents reside exclusively in a Linux tmpfs RAM disk mount. Files never touch physical non-volatile storage (NVMe, SSD, or HDD).
  • Instant Cryptographic Unlink: As soon as the output PDF or text is assembled, input files are cryptographically unlinked from memory using standard POSIX unlink() calls. Once the active conversion session terminates or 24 hours expire, RAM pages are zeroed.
  • Zero Model Training: Uploaded documents are never stored, inspected, analyzed, or used to fine-tune machine learning models.
  • Scale-to-Zero Compute: Both CPU and GPU processing containers automatically scale down to 0 instances when idle, completely clearing runtime memory.
